# 사내망 자료를 자비스가 바로 읽게 하기 (PC의 Claude 대화에 붙여 넣을 지시문)

아래 글을 사내망 서버가 있는 PC의 Claude 대화에 그대로 붙여 넣는다.

---

자비스(세컨드 브레인)가 사내망 자료를 바로 답할 수 있게, 사내망 서버가 요약 자료를 통합웹 데이터베이스(Supabase kab-shipping)에 주기적으로 복사해 올리도록 만들어줘. 먼저 find-skills와 supabase, supabase-postgres-best-practices 스킬을 불러와서 진행해줘.

## 지켜야 할 것
- 운영 데이터베이스에 표를 만드는 일이므로, 만들기 전에 표 구조와 SQL을 먼저 보여주고 내 허락을 받은 뒤에 적용한다.
- 단가, 금액, 거래처 전화번호, 비밀번호, 토큰, 엑셀·PDF 원본은 올리지 않는다.
- 사내망의 기존 기능과 화면은 바꾸지 않는다. 복사는 읽기만 한다.
- 테스트본(kab-shipping-test)에서 먼저 확인하고 운영본에 적용한다.

## 만들 것
1. 표 하나: `public.kab_intranet_snapshot` (id text 기본키, payload jsonb, updated_at timestamptz). RLS를 켜고, 읽기는 로그인한 admin·worker 역할만, 쓰기는 사내망 서버가 쓰는 권한으로만 허용한다. anon 권한은 주지 않는다.
2. 사내망 서버에서 30분마다(그리고 TASS 4시 조회 직후) 아래 묶음을 한 줄씩 upsert 한다. 묶음마다 `payload`에 `rows`와 `source_updated_at`을 넣는다.
   - `id='stock'`: 품번, 품명, 현재 재고, 7일 소요, 부족 수량
   - `id='sales'`: 이번 달 판매현황 요약(업체, 품번, 수량). 금액과 단가는 뺀다.
   - `id='tass'`: 납지카드·입고정보·자재소요 건수와 부족 품번
   - `id='meta'`: 사내망 버전, 마지막 조회 시각, 각 묶음의 행 수
3. 올리기에 실패해도 사내망은 그대로 돌게 하고, 실패는 사내망 로그에만 남긴다.

## 끝났다고 보는 기준
- 운영본에서 `select id, updated_at, jsonb_array_length(payload->'rows') from public.kab_intranet_snapshot` 결과에 네 줄이 보이고 시각이 30분 안쪽이다.
- 사내망 화면과 기존 기능이 그대로 동작한다.
- 만든 표 구조와 올리는 주기를 한 문단으로 정리해 알려준다. 그 내용을 자비스를 만든 Claude 대화("심장")에 전하면 자비스 쪽 질문 경로를 붙인다.
