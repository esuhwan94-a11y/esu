# 광고 파이프라인

광고주 한 곳의 일을 9단계로 나눠 차례로 처리한다. 각 단계는 별도 스킬이고, 앞 단계가 만든 파일을 다음 단계가 읽는다.

## 폴더 약속

광고주마다 `ads/<광고주>/` 폴더 하나를 쓴다.

| 파일 | 만드는 스킬 |
|---|---|
| `brief.md` | 이 스킬 (처음 한 번) |
| `01-시장조사.md` | ad-market-research |
| `02-고객분석.md` | ad-customer-analysis |
| `03-콘텐츠기획.md` | ad-content-plan |
| `04-카피대본.md` | ad-copy-script |
| `05-디자인/` | ad-design |
| `06-영상/` | ad-video |
| `07-채널운영.md` | ad-channel-ops |
| `08-광고개선.md` | ad-optimize |
| `09-성과분석.md` | ad-report |

## 순서

1. `ads/<광고주>/brief.md`가 없으면 `brief-template.md`를 복사하고, 빈칸을 사용자에게 한 번에 물어 채운다. 모르는 칸은 "미정"으로 두고 넘어간다. brief 없이 다음 단계로 가지 않는다.
2. 사용자가 범위를 말하지 않았으면 01~04(조사부터 대본까지)를 이어서 돌린다. 여기까지는 돈이 들지 않고 밖으로 나가는 것도 없다.
3. 05·06은 크레딧이 든다. 만들 장수와 예상 크레딧을 먼저 보여 주고 승인받은 뒤 만든다.
4. 07의 발행, 08의 광고 설정 변경은 건마다 사용자 확인을 받는다. 이전 승인은 다음 건에 이어지지 않는다.
5. 09는 광고가 돌아간 뒤에 쓴다. 지표가 없으면 건너뛰고 그렇다고 알린다.
6. 이미 있는 단계 파일은 다시 만들지 않는다. 사용자가 "다시"라고 하거나 brief가 그 뒤에 바뀌었을 때만 새로 만든다.

## 끝나고 알릴 것

- 만든 파일 목록과 각 파일의 핵심 한 줄
- 건너뛴 단계와 이유
- 사용자가 결정해야 하는 것(승인 대기 중인 생성·발행·예산 변경)

## 지킬 것

- 근거 없는 "1위", "최고", "100%" 같은 표현을 쓰지 않는다. 수치는 출처가 있을 때만 쓴다.
- 건강·의료·금융 효능은 광고주가 준 근거 자료 범위 안에서만 쓴다.
- 대가를 받고 올리는 게시물에는 광고 표기("광고", "협찬")를 넣는다.
- 경쟁사 비방, 남의 사진·음악·리뷰 무단 사용을 하지 않는다.
- 광고주 자료(매출, 고객 정보, 계정)는 외부 서비스 요청에 넣지 않는다.
